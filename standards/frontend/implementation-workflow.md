# Implementation workflow
W1 in [register](provenance.md). Engineering sequence, not a request for repeated approval.

1. Resolve mission authority, owned paths, exact baseline, runtime and accepted product/visual contract. Read entrypoint + task-selected skills; record actual load receipts rather than availability. Inspect baseline real UI, backend contract and consumers; identify highest-risk journey. Separate facts, open questions and assumptions.
2. Produce brief and route/state/authority map. Select representative screen, design grammar, token specimen and intended interaction. Establish what not to change. If product-policy question blocks an operation, continue unaffected work and surface precise dependency.
3. Build a thin vertical slice through actual target (or authorized isolated showcase). Use existing framework/primitives unless measurable gap; add tokens and adapters only as needed. Mount the screen early and demonstrate one real operator outcome. For a donor, translate visual and behavior contract without transplanting synthetic authority.
4. Iterate by real observation: compare baseline/reference/slice in same conditions, critique composition, typography, density and states; test live interaction including failure. Correct systemic causes in tokens/primitives/adapters before scaling. Add targeted regression for each discovered defect. Scope expansion or policy change requires authorization, not silent substitution.
5. Scale cohesive feature slices; each route has ownership, states, live contract, visual and responsive treatment. Track source checkpoints with exact SHA and evidence lineage; parallel lanes share runtime target and integration contracts. No fixture-only lane claimed complete. Preserve working paths, isolate flags and migrate consumers.
6. Verify production build, route reachability, role/state/interaction outcomes and visual fidelity; capture negative cases and actual runtime evidence. Distinguish local source checks, prototype, distribution, integrated and physical tests. Document remaining product gaps, not just test count.
7. Deliver exact candidate, bounded diff, acceptance matrix, before/after and unresolved limitations. Independent qualification according to mission; no self-approval or unrequested promotion. 
Proportionality: smallest change that FULLY satisfies the authorized outcome; not a license to substitute old UI or reduce product scope to pass tests. Avoid dependency churn and repeated reviews during routine authorship. On owner critique reproduce specific issue in actual surface, log observed vs inferred root cause, fix shared cause, retest affected routes, update acceptance oracle where stale (with authority; never weaken to get green).
