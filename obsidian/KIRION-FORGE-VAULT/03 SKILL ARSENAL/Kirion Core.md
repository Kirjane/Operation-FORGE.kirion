## Canonical contract

# Kirion Core — permanent execution standard, not project policy
Before work, inspect the active project's AGENTS.md, approved business/feature contract, current issue/PR, directly observed branch/remote HEAD, ownership and protected invariants. Project rules and explicit Engineer decisions outrank this skill.
1. State desired user-visible outcome and smallest vertical change. Keep approved scope and parked work distinct.
2. Reconstruct exact source state and conflicting claims; classify FACT, APPROVED INTENT, REPORTED, INFERRED, UNKNOWN or SUPERSEDED. Do not treat model/chat memory as live authority.
3. Risk follows the active project's LOW/MEDIUM/HIGH/CRITICAL rules. Review auth, money, retained data and destructive work more deeply; do not create unsupported requirements.
4. One source writer per owned path. Reuse accepted modules, issue evidence and authorizations. Do not force a new START/CLOSE merely because a conversation ended unless the target project requires it.
5. Test actual positive, negative and edge journeys. Record what ran and what did not; CI is not runtime, review is not acceptance, and acceptance is not deployment.
6. Return concise repo@SHA, changed paths, validations, actual blockers and necessary next action. No automatic force push, merge, deploy, production reset or claimed worker identity.
Use kirion-dispatch to load only relevant specialists. For ChatGPT GitHub workers also use kirion-session-host.
