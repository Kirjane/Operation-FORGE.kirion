# Responsive design and accessibility
Sources R1–R2. Existing frontend_web profile at pinned baseline defines viewports 1440x900, 1280x720, 1024x768, 768x1024, 390x844, 320x568 and WCAG 2.2 AA. Keep these for that profile; supplement with actual device and contract.

## R1 — Content-width design (MUST)
Determine minimum content width from columns, controls, language, font and sidebar; use available width rather than device labels. Example: viewport 1024 minus 248 rail and 48 gutters leaves 728 for a register; if it needs 900, collapse navigation, prioritize columns, change to structured cards or provide intentional labelled local scrolling with accessible equivalents. A two-dimensional data table may need scroll, but page overflow is not a solution. Keep table semantics where comparison is core; card variant must expose all required fields/actions and avoid duplicate focusable hidden content.
Use flexible grid tracks (minmax(0,1fr)), min-width:0, logical spacing, wrapping, responsive images, safe area and dynamic viewport handling where supported. Never hide required actions merely to fit. Test virtual keyboard, landscape, device scaling, zoom, text growth, long words, large numbers and sticky headers/footers. Select breakpoints by observed failure; 1280 in OT and 1024 rail collapse in SC are examples, not universal.

## R2 — Accessible by construction (MUST)
Use semantic landmarks with one primary main and appropriate nested section headings; a section header is valid inside main, global banner/nav semantics need appropriate scope. Accessible names, explicit field labels, grouping, error associations, keyboard order, visible non-obscured focus, no color-only meaning, meaningful alt, screen-reader-compatible status and predictable dialogs. WCAG 2.2 AA: normal text contrast at least 4.5:1, large text 3:1; applicable non-text UI contrast 3:1; minimum target size 24 CSS px or applicable exceptions, with larger ergonomic targets (44–54 illustrative) for frequent touch. Verify reflow and text resizing under WCAG applicability. Use reduced motion, forced-color handling, accessible chart alternatives, and avoid auto-zoom issues on target mobile platforms. 
SHOULD combine token checks, automated axe, keyboard/manual screen reader sampling and real device interaction. Axe zero serious/critical is not conformance and does not cover aesthetics or all routes. Test disabled and error states, overlays, date pickers, navigation, tables, focus after mutation, 200% text and 400% zoom/reflow where applicable. 
Acceptance: no unintended page overflow, all required tasks usable in applicable viewport/input/zoom, no clipped or obscured focus/primary controls; document scoped automated and manual results and untested devices.
