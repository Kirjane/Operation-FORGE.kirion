# Frontend quality
Use client's accepted IA, visual references and actual data/routes, not invented text, maps, records, counts or unauthorized destinations. Build clear hierarchy, responsive layout, keyboard/focus contrast and truthful loading/error/empty/permission states.
Preserve server authorization even when changing visible menu items. Test actual desktop/mobile breakpoints, permitted roles and denied routes with browser screenshots. Check overflow, focus, active navigation, accessibility and browser errors. A nice mock is not production acceptance. Use smallest reviewable changes; do not opportunistically rewrite backend/business rules.
