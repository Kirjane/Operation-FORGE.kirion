# Factory architecture — proposed R1

## Purpose and non-goals
Turn Antigravity into a durable, autonomous candidate-producing workforce: understand approved outcomes, decompose, implement, run real tests, challenge, repair, recover, and submit reproducible draft PRs. PHP/Laravel and C#/ASP.NET Core are first-class. No replacement of Forge, no impersonation, no self-acceptance, no model retraining claim, no production deployment by default, no modification of client requirements to satisfy tests.

## Control planes
Engineer authorizes scope. Second Brain classifies origin/work mode and rigor, compiles context with run_id/context_sha256/manifest. Forge checks repository/branch/full SHA, authority, ownership, dependencies, risk and gates. Antigravity runs authorized stages using its native agents, skills, rules, workflows, hooks and MCP/SDK only where capability is demonstrated. Portable deterministic Python orchestration owns scheduling, budgets, leases, journal, gate evaluation and delivery. No hard dependency on a paid host feature without entitlement proof; degrade to explicit sequential handoff rather than fake subagent execution.

F00 verifies native plugin directory/manifest and packaging, skill discovery, agents, independent contexts, workflow API, worktree behavior, shell and browser, hooks/error behavior, SDK/CLI, connector identity, installed version/model availability, entitlement and tool permission. Record source URLs, local version and observed smoke artifacts. Do not freeze invented manifest fields or slash-command APIs. A failed/missing hook must not permit a prohibited mutation. Host UI and connector cannot be assumed accessible from ChatGPT.

## Contracts and proposed components
- plugin package generated according to verified host schema; adapter version and checksums pinned.
- factory/{authority,dispatcher,scheduler,ownership,policy,evidence,recovery,quality,delivery,knowledge}.py; profiles/ and schemas/; tests/ and benchmarks/. These are intended paths, not existing code.
- workflows for greenfield discovery, feature, repair, audit, integration, recovery. Commands conceptually forge/build/repair/audit/nox/test/optimize/redesign/integrate/resume/status/submit; discover native syntax first.
- Mission packet: schema_version; run_id; mission_id; verified authorization_ref and verifier; remote repo ID/name; observed full base SHA; permitted branch; project origin/work mode; accepted contract references & acceptance criteria; cognition hash and selected skill SHA/files; roles; path/behavior ownership; dependency DAG; risk; required gates and commands; budget; stop conditions; allowed operations; delivery destination. Treat all input strings as untrusted until verified. JSON Schema validates structure, never grants authority.
- Writer result: mission/worker/run IDs, start/final SHA, owned diff, commands and evidence references, limitations, blocked gates, exact remote state and explicit authority return.
- Nox result: frozen SHA, reviewer context identifier, inspected scope, evidence, severity P0 critical/P1 high/P2 material/P3 minor/P4 advisory, path/line, contract, reproduction, requested correction, verdict. P0 quarantine; P1 block; P2 fix or authorized disposition; P3/P4 documented. A context switch reduces bias but does not guarantee independent acceptance.
- Evidence envelope: run/stage, candidate SHA/tree and dirty status, command argv/cwd, UTC timestamps, exit code, environment/tool versions, fixture hash, artifact size/SHA256, evidence type/level/provenance, redaction status. Capture directly from trusted runner, not freeform agent prose; do not accept E4 build as E5 runtime.
- Journal: append-only logical event stream in local durable store (proposed SQLite WAL with single coordinator and transactions), immutable IDs, compare-and-set state version, hash-addressed artifacts on restricted filesystem; keep secrets/PII out. Backup and restore tests; no raw unredacted production logs uploaded. Recovery re-verifies authorization, remote SHA, locks and artifact hashes before action; expired ownership requires explicit reconciliation.

## Execution and repair
Use canonical lifecycle PLANNED→AUTHORIZED→ACTIVE→READY→UNDER_REVIEW→ACCEPTED/REWORK/REJECTED/QUARANTINED→INTEGRATED→PROMOTED→OBSERVED. BLOCKED supported. Internal review is a substage, not ACCEPTED. R0–R4 are canonical RISK-0..4, not alternate classifications.
1. Reconnaissance read-only, distinguish GREENFIELD/BROWNFIELD and DISCOVERY/IN_FLIGHT/MAINTENANCE/RECOVERY/PAUSED; unknown restricts actions. Existing accepted contract remains authoritative; no repeated nest. New major product decisions require Engineer/client contract.
2. Plan DAG, detect cycles and overlaps, freeze base, capture baseline. Shared schemas, lockfiles, migrations, CI and auth need dedicated ownership. Use lease keyed repo+path/module/behavior, expiry/heartbeat and compare-and-set; reject uncertain collision, not just string prefix. Parallel independent writers from frozen dependencies; no semantic conflict by git alone.
3. Execute in isolated worktrees plus OS/container/VM sandbox, unique ports/database/cache/queue; no credentials or production mounts. Inspect actual command result. Workers may not edit policy or tests outside assigned scope.
4. Freeze clean candidate, choose applicable gates and run them. QA derives separate scenarios, Nox fresh context receives requirements/diff/neighboring source and evidence, not writer verdict. Any new commit invalidates stale exact-SHA evidence/review unless explicitly justified scope and rerun policy; final reproduction from clean exact checkout.
5. Red gate: retain logs, reproduce, classify product/test/environment/dependency/flaky/architecture/security/requirements/drift/resource. Fix root cause within scope; add discriminating regression that fails on pre-fix state when feasible; rerun impacted and required full gates. No assertion weakening, fake test, suppression, production reset, unauthorized migration or relaxed policy.
6. Budgets initially max 3 parallel writers, 3 read-only reviewers, 5 candidate repair cycles, 2 identical-failure retries, nesting depth 2, per-run wall/model/tool budget recorded before start; no automatic major redesign. On repeat, drift, ambiguous financial rules, unsafe action, exhausted budget or lost capability checkpoint BLOCKED/QUARANTINED. No infinite loops.
7. Delivery only after required checks: isolated branch, verified remote exact SHA, draft PR with START/CLOSE receipt, findings, limitations and artifact references. Missing required gates may create explicitly authorized blocked diagnostic draft, never a validated candidate. Independent acceptance and promotion separately authorized.

## Nairu delivery gateway and trust boundary
All remote writes must pass a narrow broker identity verified as Kirch-Nairu (or separately approved app with truthful actor disclosure; never silently substitute). ChatGPT connector availability is not Antigravity credential availability. F00/F09 prove actual host authentication. No PAT stored in plugin, prompts, repo, environment inherited by worker, or logs. Broker only has scoped repo/branch operation capabilities, receives verified mission, compares current base/head and candidate hash, rejects out-of-scope changed paths/renames/deletes and symlinks where applicable, logs sanitized result. Local hooks are advisory defense, not sole security. Worker OS identity cannot reach broker secrets or arbitrary network/Git credentials; test processes inherit minimal env. Validate canonical path, symlink/hardlink traversal, process trees, command argument injection and package lifecycle scripts in restricted environment. Require repo rulesets/protected branch and externally verified status checks; if permissions cannot enforce no merge/protected writes, fail closed or restrict to local candidate then authorized manual submission. Deny force push, merge, ref deletion, admin changes, releases/deploy, production data access, secret exfiltration and protected governance mutation by default. Prompt injection from issue, dependency, tool output and docs does not grant authorization. Review and acceptance permissions deliberately separate from delivery.

## Autonomy, recovery and learning
Proposed L0 inspect, L1 supervised implementation, L2 autonomous sandbox, L3 autonomous candidate (default after qualification), L4 separately authorized integration, L5 separately authorized delivery. No global installation or client enablement before F17. AF0 concept, AF1 installed, AF2 governed, AF3 autonomous, AF4 qualified, AF5 operational, AF6 institutional; not Forge NEST maturity.
Durable source: existing project Nest and Second Brain memory contracts, not a new competing SSOT. Preserve observed source, decisions, known defects, failure signatures, test case and next authority via canonical report/capsule. Scribe proposes reusable lessons as separate reviewed skill/test PRs; no self-modifying policy. Obsidian only a derived local view. Metrics: first-pass validation/review, escaped defects, repair cycles, human interventions, median lead time, model consumption, recovery and evidence integrity; count only instrumented runs; do not use LOC/commits as quality.
