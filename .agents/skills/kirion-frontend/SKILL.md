# Frontend quality
Follow the client's approved IA, visual references, routes and data contract. For real systems, never invent factual text, maps, records, counts or unauthorized destinations. For an **explicitly authorized static showcase**, clearly labeled fictional sample records, counts, status histories and simulated role views are permitted; identify official-looking documents as SAMPLE / INVALID. Never present a mock as live data, real login, ecclesiastical approval or backend permission enforcement. Build clear hierarchy, responsive layout, keyboard/focus contrast and truthful loading/error/empty/permission states.
Preserve **actual server authorization where it exists**, even when visible menu items change; a simulated role switch is not authorization. Inspect desktop/mobile breakpoints and browser screenshots; test real permitted/denied routes where authentication exists, or demonstration navigation/role affordances where it does not. Check overflow, focus, active navigation, accessibility and browser errors. A polished mock is not production acceptance. Prefer the smallest reviewable change; do not opportunistically add backend/business rules.
