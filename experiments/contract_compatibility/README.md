## Model surfaces

`validate_raw` handles strict raw ingress; `parse_record`, `canonical_bytes`, `digest`, and `record_ref` expose deterministic data transformations. `validate_record` and `validate_graph` inspect supplied primitive records and typed earlier references. `reduce_decision` returns a closed reducer result and separate snapshot; publication and staging are only in-memory descriptions. `evaluate_context`, `evaluate_command`, `evaluate_attempt`, `evaluate_evidence`, and `evaluate_acceptance` accept explicit independent fixture inputs. No API accepts a callable or selects a live resource. The JSON schema documents the closed record variants; lexical, canonical-order, graph, and policy constraints are checked in the model, not by a general JSON Schema engine.

Raw SHA-256 is separate from the full-envelope model digest. Canonical key order is Unicode scalar order, strings use literal UTF-8 except quotes, backslashes and lowercase control escapes, arrays retain order, and declared sets must already be strictly ordered by canonical element bytes. No normalization. Decision expiry and history use supplied ticks, not a clock. Logical operation keys survive lineage changes; only the attempt predecessor may cross lineage within the same repository. Independent expected controls are evaluated for exact applicability before verdict; a matching disconfirming control is a model match, not a product failure. Actual external fencing, one-winner concurrency and trust are outside this experiment.
