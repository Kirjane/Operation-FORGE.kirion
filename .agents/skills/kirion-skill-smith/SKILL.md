# Disposable mission-skill smith
Create a temporary skill only when an existing skill cannot cover a nontrivial, source-specific multi-step task and writing the capsule will reduce real coordination. Do not create one for an ordinary bug or repeatable feature.
Use VM temporary storage by default, not shared repo/global policy. Content must include task ID, exact repo/SHA or UNVERIFIED, owned scope, allowed/forbidden actions, sourced procedure, actual acceptance proof, stop conditions and explicit expiry. Never install globally, change AGENTS/GEMINI, merge, grant permissions or pretend a temporary VM survives another conversation. If authorized to commit the task skill, scope the commit to the assignment and verify it.
Include an adversarial test: does the instruction refuse unauthorized writes, fake PASS, stale SHA and unrelated scope? When finished, retire the capsule; only propose a stable skill after observed repeated usefulness and independent Engineer approval.
